# v0.1 验收范围

自动检查均使用虚构数据与临时目录；默认不联网，不向联系人发送消息，不弹桌面通知。

| 检查 | 通过条件 |
|---|---|
| 人格构建 | 模型符合仓库 schema、模板占位符完整替换、生成卡与源码一致 |
| 初始权限 | 四项默认关闭，主动调度默认关闭；没有私人授权文件 |
| 记忆 | 无授权进入带 TTL 的缓冲；摘要不会跨主体/渠道读取；撤权后不注入 |
| 状态 | 相同 event_id 不重复增长；正向自然日上限生效；人格模型不被状态改写 |
| 投递 | 未到期、过期、安静时段、撤权及上限均可拦截；force 不绕过 |
| 并发 | 同任务并发 accept 最多写入一条，不同任务不并发突破额度 |
| 恢复 | 恢复前撤权/过期/安静时段均不追加；崩溃已写记录只对账 |
| 发布 | 精确文件清单，不包含本地诱饵数据；ZIP 名称唯一、哈希全部匹配、清单不包含自己 |

本地通过结果应记录在发行说明中。GitHub Actions 配置提供 Windows / Ubuntu 的 Python 3.11、3.13 检查矩阵；只有实际运行成功才能声称远端 CI 通过。

这些是工程行为检查，不评估真实模型的人格还原率、情绪自然度、长期陪伴效果或平台可用性。真人盲测、真实云接口、系统托盘通知、多用户、时区迁移、断电和损坏恢复均需独立验收。
