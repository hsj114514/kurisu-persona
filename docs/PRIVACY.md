# 隐私与安全边界

发布文件由 release-files.json 精确列出；个人授权、聊天、状态、调度数据库、inbox、日志、密钥与语料不在清单。`.gitignore` 是辅助措施，不会抹去已经提交到 Git 的内容。发现误提交密钥后应撤销密钥并处理历史，不要只删除当前文件。

本地文件使用普通 JSON / JSONL / SQLite，**没有加密**。应限制电脑账户和备份访问，避免同步到共享目录。提示词中的“仅作数据”标签和禁用短语只是防御措施，不能保证模型完全抵抗注入。宿主不得执行记忆、小说、模型回复中出现的命令或工具请求。

当前 outreach / composer / schedule 仅用于本地单用户 local。部分记忆函数可按主体/渠道过滤，但这不等于完整多用户安全边界。接入真实消息平台前，还需验证账号、群聊/私聊、用户和人格隔离，逐人同意，撤权传播，平台发送回执、幂等、限流，以及网络接口的最新文档。此仓库没有实现或验证这些平台 API。

JSONL 记忆与授权更新不适合多个写入进程。投递部分用 SQLite 写锁串行化同一数据库下的 accept / recover，并以任务 ID 防止重复追加；外部直接编辑、损坏磁盘、文件回滚和多个不同数据库共用 inbox 不在保证范围内。不要将数据库和 inbox 拆成不同持久卷。

若发现问题，请通过仓库 issue 提供最小虚构复现；不要提交真实聊天、健康经历、密钥、原作文本或整个运行目录。当前没有私密漏洞报告通道，敏感细节不适合公开 issue。
